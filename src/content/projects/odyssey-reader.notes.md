## 0. 先说最要命的一件：这个页面有三份拷贝

同一份 HTML 现在存在三个地方，**它们之间没有任何构建步骤或同步机制，会漂移**：

| 位置 | 形态 |
|---|---|
| `yaneryang` 仓库 `public/odyssey/index.html` | 完整文档（有 doctype / head / meta），网站上线用的就是这份 |
| `Rougeetnoir/Reader` 仓库（私有）`odyssey.html` | **没有 doctype、没有 `<head>`**，从 `<title>` 直接开始 |
| Claude Artifact（`claude.ai/code/artifact/f5775b09-daee-4d89-83a8-576350cefa9e`） | 由 Reader 那份发布，宿主自动包 head |

Reader 那份之所以缺 head，是因为 Artifact 宿主会自己套
`<!doctype html><head>…</head><body>`，我按那个约定写的。后来要放到网站上
才补的 head——**补 head 是一次性的手工操作，脚本没留**。做法是：按
`\n<header class="hero">` 把源文件切成两半，前半（title + link + style）塞进
`<head>`，后半塞进 `<body>`，再在最前面加 doctype、`charset`、`viewport`、
`color-scheme=dark`、favicon 链接。`viewport` 那行是必须的，Artifact 宿主会自动加，
静态托管不会——漏了手机上会当成 980px 桌面页渲染。

**2026-08-26 起漂移更严重了**：网站这份加了 19 张内联的演员头像（见第 7 节），
另外两份没有。要同步它们，不是复制粘贴几行就行，得把整个
`ODYSSEY-FACES` 区块搬过去——那是一百多 KB 的 base64。

**建议**：以后只维护 `public/odyssey/index.html` 这一份，Reader 仓库那份当归档。
如果一定要两边都活，改完记得手动同步，并且注意 Reader 那份不能加 head
（加了 Artifact 发布会重复）。

顺带一个本地预览的坑：Reader 仓库那份没有 `charset`，用
`python3 -m http.server` 打开会整页乱码（Python 不发 charset，浏览器猜成 latin-1）。
`public/odyssey/index.html` 这份没这个问题。

## 2. 地图与 SVG 坐标

### 坐标系

`viewBox="0 0 1040 820"`，**纯示意布局，和地中海地理没有任何关系**。别试图
按真实航线重排——荷马的地理本来就无法定位，而且按语义分组读起来更快。

五个区块：

| 区 | 大致范围 | 谁在里面 |
|---|---|---|
| 众神 | 顶部横带 y≈48–172 | 宙斯、雅典娜、波塞冬、赫尔墨斯 |
| 伊萨卡 | 左侧 x≈86–312 | 家人、老仆、狗 |
| 归途遭遇 | 右侧 x≈608–966 | 女巫、巨人、海妖、船员 |
| 求婚者 | 左下 | 4 个 |
| 特洛伊战场 | 右下 | 5 个 |

`odysseus` 在正中 (500, 340)，`r:26`，是全图唯一半径超过 20 的节点——他是枢纽，
所有区块都往他连线。

### 全部坐标是手排的，没有布局算法

**没有用力导向布局。** 不是试过失败，是一开始就没做，理由有两条：手排能保证
每次打开位置完全一样（这是个参考工具，位置漂移会毁掉肌肉记忆）；力导向
排不出「众神在上、家在左、海在右」这种本身携带信息的空间语义。

### 手工微调过、不能靠公式重算的值

看过一次渲染之后，我把特洛伊那一组整体往上挪过：

```
menelaus      592,700 → 566,684
helen         716,748 → 700,742
clytemnestra  960,720 → 936,684
agamemnon     846,646 → 832,630
melantho      438,690 → 430,702
```

原因是**标签会超出 viewBox 底边**。每个节点画两行文字，
中文标签在 `y + r + 16`，英文小标在 `y + r + 28`（见 L891–892 的 `t1` / `t2`）。
所以有一条硬约束：

> **`node.y + node.r + 28` 必须小于 820。**

同理，标签是居中对齐的，**贴近左右边缘的宽标签会被裁**。
目前最险的是 `scylla`（x=966，标签「斯库拉与卡律布狄斯」9 个字，
12.5px 下约 113px 宽，右端到 ~1023，只剩 17px 余量）。**再往右挪就会裁掉。**

挪任何一个节点，唯一的连带影响是连线端点（`LINKS` 靠 id 查坐标，自动跟着走）
和视觉密度。没有别的隐藏耦合。

### 节点底下那个黑圆是干什么的（L886）

```js
g.appendChild(svgEl('circle',{cx:c.x,cy:c.y,r:c.r,fill:'#070B10'}));
```

连线是圆心到圆心画的，画在节点组下面。这个不透明黑圆的唯一作用是**把穿过节点的
连线挡住**，让线看起来是「连到节点边缘」而不是「从节点中间穿过去」。

两个坑：

1. **`#070B10` 是硬编码的**，不是 CSS 变量。它取自页面底色 `--abyss`（L16）。
   改配色时这里不会跟着变。
2. 它**并不等于** map-box 的背景（那是个 `#0E1B26 → var(--sea)` 的径向渐变，L167）。
   也就是说这个圆比它周围略深一点点，节点看起来微微「凹」进去。
   **说实话这不是设计出来的，是我当时随手取了页面底色。** 视觉上过得去，
   但别把它当成有意为之的效果去保护。

### 命中区（L894）

```js
const hit = svgEl('circle',{... r:Math.max(c.r+8,22)});
```

透明圆，**必须是节点组的最后一个子元素**（在最上层）才能接住指针事件。
文字设了 `pointer-events:none`（L174，`.node text`），否则标签会挡住命中区。
**如果重排 `<g>` 的子元素顺序，小节点的 hover 和点击会静默失效。**

### 断点 1320px 是量出来的，不是拍脑袋

`.map-layout`（L152）在 ≥1320px 是「图 + 右侧详情栏」两栏，详情栏固定 340px。
低于 1320px 单栏。这个数字的来由：详情栏占掉 340 + 24 gap 之后，1320px 大约
给图留 890px，viewBox 1040 缩到 0.86，12.5px 的标签落到约 10.7px——再窄就
读不了了。**这个断点关心的是地图能不能读，不是手机。**

最初的值是断点 940px / 详情栏 350px / `svg{min-width:820px}`，结果在
1280px 屏幕上地图被挤到 760px 宽，一直横向滚动。改成现在这样的同时，给
第二个 `<section>` 加了 `.wide`（L151，max-width 1440）让它比全站 1180px 更宽。

## 3. 时间线的双排序

### 数据结构

`EVENTS`（L650）是一个**无序**数组，每项有 `id`（`e0`…`e16`）。
顺序完全由另外两个数组决定：

- `ORDER_STORY`（L704）—— 事情实际发生的先后
- `ORDER_HOMER`（L705）—— 荷马的讲法（中途切入 + 倒叙）

`renderTL(order)`（L980）按选中的数组取 id，从 `EV_BY`（L979）查对象。
**`EVENTS` 里的声明顺序完全不起作用**——`e13` 现在夹在 `e11` 和 `e12` 中间，
只是因为它是后加的。别去「整理」它，没有意义，也别指望它有意义。

### 加一个新事件要改三处

1. `EVENTS` 里加对象
2. `ORDER_STORY` 里加 id
3. `ORDER_HOMER` 里加 id

**漏掉后两个中的任何一个，这个事件就静默消失，不报错、不警告。**
没有任何校验。这是整个文件最容易踩的坑。

（想加保险的话，在 `renderTL` 里比对一下 `EVENTS.length` 和两个 order 数组的
长度，不一致就 `console.warn`。当时没做。）

### `sub` 和 `book` 在两种模式下会对调

看 `renderTL` L980 起：故事顺序下，右上角小徽章显示 `e.sub`、下面副标题显示
`e.book`；荷马顺序下两者互换。所以写新事件时：

- `sub` 要写成**地点或时间**（「伊斯玛洛斯 · 出发后数日」）
- `book` 要写成**在诗里的位置**（「第九卷」）

写反了不会报错，但切换模式后会读起来很怪。

左边的序号是渲染时按数组下标现算的（`String(i+1).padStart(2,'0')`），
不存在数据里，所以插入事件后自动重编号。

## 4. 试过之后推翻的方案

按有用程度排：

**① `main.wrap` 包住所有 section → 每个 section 自己带 `.wrap`**

原来是 `<main class="wrap">` 统一控制宽度。为了让人物图那一节能撑到 1440px，
改成每个 `<section>` 自己挂 `.wrap`。**这一改直接引出了下面第 5 节第一条那个
padding 塌掉的 bug。** 改完必须检查页面左右还有没有留白。

**② 详情栏原来在网格的左列里面**

最初 DOM 是 `.map-layout > div(地图 + 名单) + aside.detail`，名单和地图捆在一起。
结果在单栏（<1320px）下，顺序变成 地图 → 31 个名字的按钮墙 → 详情栏，
点一个名字要翻过整面按钮墙才能看到结果。**把名单挪出网格**之后顺序才是
地图 → 详情 → 名单。别再把它挪回去。

**③ 非邻接节点的暗度 .22 → .42**

原值 .22。渲染出来半张图几乎看不见，看起来像坏了。.42 是能看清又明显退后的值。
（L180）

**④ 双主题（浅色 + 深色）—— 主动放弃，不是没做完**

全站规范是要求三态主题（`:root` 浅色 + `prefers-color-scheme` + `[data-theme]`），
这个页面**故意只做了深色**，理由是它是进影院前看的东西，而且和这部片的影像一致。
后果要说清楚：**它没有任何 `prefers-color-scheme` 处理，也没有 token 分层。**
将来真要做浅色，是从头搭一层 token，不是加个 media query 就行。

**⑤ 力导向布局 —— 考虑过，没写代码**

理由见第 2 节。这条只是为了让你不用再想一遍。

## 5. 地雷区

### `.wrap` + padding 简写 = 左右内边距静默消失

**这是这个文件里最阴的一个坑。** `.wrap`（L59）现在写成
`padding-left:24px; padding-right:24px;`（**不是简写，是刻意的**）。

因为 `.panel-sec`（L112）、`.hero-in`（L76）、`footer`（L283）都定义在 `.wrap`
后面、都同样是单类选择器、而且都设置 `padding` **简写**。简写会把
`padding-left/right` 一起重置成简写里的值。之前它们写的是 `padding:56px 0 96px`，
于是整页左右贴边。

> **规则：任何同时挂 `.wrap` 和另一个类的元素，那个类里的 `padding` 必须
> 显式带上左右值（现在都是 24px），或者别用简写。**

L288 那个 640px 以下的媒体查询里同样带了左右值（20px），改的时候一起注意。

### 演员名存了两份

## 6. 约束

### 单文件、无构建（**运行时仍然成立，但现在有一个生成步骤**）

这是硬约束（要能作为 Artifact 发布、要能当静态资源塞进 `public/`、要能离线打开）。

**2026-08-26 更新**：加演员头像之后，页面在**运行时**依然是零依赖的单文件，
但它不再是纯手写的了——`ODYSSEY-FACES:BEGIN` / `:END` 之间那段 base64 由
`scripts/build-odyssey-faces.mjs` 生成。见第 7 节。

代价：

- 数据和视图挤在同一个文件里，1037 行。
- 没有类型检查。`CHARS[].f` 写错一个阵营名不会报错，只会 `FACTIONS[c.f]` 拿到
  `undefined` 然后在取 `.c` 时炸掉。
- 没法和网站共用任何 CSS token，配色是完全独立的一套。
- 三份拷贝会漂移（见第 0 节）。

### 外部依赖只有一样

严格说**只有一个外部来源：Google Fonts**（三个字族，L10–12）。没有 JS 库、
没有 CSS 框架、没有图标字体。

- **Cinzel** —— 拉丁碑刻体，只用在英文人名、罗马数字标号、小字标签。
  它**没有任何 CJK 字形**，所以每个用到它的 font stack 里都必须跟一个 Noto SC
  兜底，否则中文会掉进系统默认（Windows 上是宋体）。
- **Noto Serif SC** —— 中文标题。
- **Noto Sans SC** —— 中文正文。

选 Google Fonts 而不是自托管，是因为 **Artifact 的 CSP 只放行
`fonts.googleapis.com` / `fonts.gstatic.com`，别的字体主机一律被拦**。
在网站这一侧本来可以自托管（全站其它字体就是构建时自托管的），
但为了三份拷贝行为一致，没有分叉。字体加载失败页面仍可用，
fallback 里写了 PingFang SC / Songti SC。

### 响应式取舍

- **地图在窄屏不重排，改成横向滚动**（`.map-box` 外层 `overflow-x:auto`，
  `svg{min-width:700px}` L169）。关系图本来就没法 reflow，宁可滚。
- 详情栏在 ≥1320px 是 `position:sticky; top:78px`，以下变 `static`。
- 页面主体任何时候都不该横向滚动，只有地图那个容器自己滚。改宽度相关的东西时
  检查一下 `document.documentElement.scrollWidth > innerWidth`。

### 嵌在网站里的那层

网站项目页通过 `src/components/DemoEmbed.astro` 用 iframe 嵌这个页面，
sandbox 是 `allow-scripts allow-same-origin allow-forms allow-downloads`。
**`allow-scripts` 是标签页切换能工作的前提**——收紧 sandbox 会让它退化成
一张 hero 静态图。

`odyssey-reader.mdx` 的 `demo.url` 必须是绝对 URL（content schema 里是
`z.string().url()`），所以它永远指向线上的 `https://yaneryang.pages.dev/odyssey/`。
**本地 `astro dev` / `astro build` 时那个 iframe 会显示线上站的 404 回落页
（看起来像首页），这不是 bug。**

### 这份文档本身

放在 `src/content/projects/` 下但扩展名是 `.md`；三个 content collection 的
glob 都是 `**/*.mdx`（`src/content.config.ts` L12/43/67），所以它不会被
Astro 当成内容条目，不进构建。**别改成 `.mdx`**，一改就会因为缺 frontmatter
让整个构建挂掉。

## 7. 演员头像（2026-08-26 加）

星图里 19 个节点的圆圈里放了演员头像，演员对照页每张卡片右上角放了同一张。
这一节写的是这套东西的坑。

### 为什么必须内联成 base64

试过的替代方案全部走不通：

- **外链**（TMDb 的图床）——Artifact 的 CSP 只放行 Google Fonts，直接被拦。
- **放 `public/odyssey/portraits/`**——网站这份能用，但 Artifact 那份会 404，
  离线打开也会全裂。

所以只剩内联。`ODYSSEY-FACES:BEGIN` / `:END` 之间那一段是
`scripts/build-odyssey-faces.mjs` 生成的，**不要手改**。流程写在 `CLAUDE.md` 里。

实际体积：19 张 128px WebP 共 35KB，转成 base64 后 48KB，
整个文件从 72KB 涨到 120KB。

`FACE_SRC` 按演员 slug 存图，`FACE_BY_CHAR` 把 `CHARS[].id` 映射到 slug。
分成两张表是因为露皮塔·尼永奥一个人对应 `helen` 和 `clytemnestra` 两个节点，
合成一张表的话她那几 KB 要存两份。

### 19 / 31

只有已公布卡司的角色有脸。宙斯、波塞冬、赫尔墨斯、埃俄罗斯、瑙西卡、
欧律克勒亚、拉厄耳忒斯、安提克勒亚、欧律马科斯、塞壬、斯库拉、阿尔戈斯
这 12 个维持原来的空心彩环。**这是有意的**，不是没做完——有脸=电影已公布卡司，
没脸=纯原著人物，而且给一条狗和一群海妖配头像本来也很怪。图例那句小字说的就是这个。

特拉维斯·斯科特（吟游诗人）反过来：他有卡片头像，但星图里没有对应节点。

### `<g>` 的子元素顺序又多了两个成员

第 2 节那条「`.hit` 必须是最后一个子元素」现在更容易踩了。完整顺序是：

```
黑色垫底圆 → image.face → circle.tint → circle.ring → text → text.en → circle.hit
```

- `image.face` 必须在 `ring` **之前**，否则阵营描边被照片盖住。
- `.node image.face` 设了 `pointer-events:none`，和 `.node text` 同理。
- **有头像的节点，`ring` 的 `fill-opacity` 是 0**（无头像时是 .15）。
  忘了这条的话，环的半透明填充会和 `tint` 叠成双重上色，照片会糊掉一层。

### clipPath 为什么是每节点一个

用的是每节点一个 `userSpaceOnUse` 的 `<clipPath id="fc-<id>">`，放在 `<defs>` 里。
看起来啰嗦——理论上一个 `clipPathUnits="objectBoundingBox"` 的圆就能给所有节点复用。
**没这么做是因为 Safari 对 `<image>` 上的 objectBoundingBox 裁剪历史上有 bug，
而这个页面从来没在 Safari 上测过**（见第 5 节「已知未修」）。19 个 defs 不值得
为省事去赌。

### 裁剪策略：`top`，不是 `attention`

`sharp` 的 `position` 用的是 `'top'`——从 2:3 竖版原图顶部取正方形。

**先试的是 `sharp.strategy.attention`（显著性裁剪），19 张里错了 3 张**：
汤姆·赫兰德、乔万·阿德坡（白衬衫）、露皮塔·尼永奥（亮黄色高领）。
显著性算法找的是高对比区域，不是脸，于是衣服赢了头，裁出来是下巴加半身。
TMDb 的 profile 是标准化头像、脸恒在上三分之一，这种规整格式上按顶部裁比
猜显著性稳。换成 `top` 之后三张全部修好，其余 16 张没有一张变差。

个别还是不满意的，在 `scripts/odyssey-faces.json` 里给那个人加 `crop`
字段（`sharp` 的 `extract` 参数），脚本会改用它并退回 `centre`。

### 脱色是 CSS filter，不是图片本身

图片存的是彩色原图，脱色靠 `.node image.face{filter:grayscale(1)…}`，
悬停/选中时换成 `grayscale(0)`。所以：

- **改配色时这层 filter 要一起想**，它和阵营色的 `tint` 是配合着调的
  （默认 tint .28，选中降到 .06）。
- 用 resvg 之类的非浏览器渲染器给这个 SVG 出图时，CSS filter 不生效，
  出来的东西和实际观感不一样。**别拿那种图判断视觉效果。**

### 验证时的坑（真踩过）

- **`@resvg/resvg-js` 2.6.2 解不了 WebP**，头像会静默不画，渲出来是一堆暗盘。
  不是页面的问题。
- 浏览器里把这个 SVG 序列化成 `<img>` 再画进 canvas 采样，也拿不到正确像素。
- 真正有效的检查是直接问 DOM：`new Image().src = FACE_SRC[…]` 看
  `naturalWidth` 是不是 128，以及用 `Range.getClientRects()` 量文字的真实右边界
  （量 `.an` 这种块级元素的 `getBoundingClientRect().right` 永远顶到内容盒右缘，
  会假报「文字和头像重叠」）。

### 卡片头像的布局约束

头像 `position:absolute` 在卡片右上角，占 y≈18–76px。只有 `.an` / `.arrow` / `.cn`
这三行在这个高度上，所以只给它们加了 `padding-right:74px`，`.cen` 及以下没加。
**换更大的头像或改 `.actor` 的 padding 时，这三个数要一起改。**
640px 以下头像降到 48px、`padding-right` 降到 62px。

注意 `.actor` 用的是 `padding` 简写，但这次没碰它，所以不涉及第 5 节那个
`.wrap` padding 塌陷的雷。

### 署名是义务

页脚 `#srcNote` 里那句「本页使用 TMDB API，但未获 TMDB 认可或认证」是 TMDb
使用条款要求的，**不能删**。

## 9. 中英双语（2026-08-28 加，**尚未完成**）

导航栏右侧有 `中文 / EN` 开关。**当前只完成了一部分**，见本节最后的进度表。

### `T()` 与字段形态

```js
const T = v => (v && typeof v==='object' && !Array.isArray(v)) ? (v[LANG] ?? v.c) : v;
```

`LANG` 是 `'c'`（中文）或 `'e'`（English）。可翻译字段写成 `{c:…, e:…}`，
**普通字符串照旧**（两种语言相同的东西，比如希腊文 `gr`、序号 `n`、颜色）。
缺 `e` 时回落到 `c`——所以还没翻译的部分只会显示中文，不会崩，
也一眼看得出哪些没做。这是刻意的：翻译是分批进行的。

**结构性字段一律没有双语化**：`id` / `x` / `y` / `r` / `f` / 各种颜色。
星图坐标是手排微调过的（见第 2 节），复制成两份迟早会漂。

### 名字字段不是 i18n 字段

`CHARS[].zh` / `.en`、`CAST[].a` / `.ae` / `.c` / `.ce`、`GODS[].zh` / `.en`
这些**本来就是"同一个东西的两种写法"**，不是 `{c,e}` 结构。渲染时按 `LANG` 选：

- 中文界面：中文名为主，英文名作小字副标
- 英文界面：**只显示英文名**，再摆一行中文对英文读者没有用

星图节点尤其注意：中文界面画两行文字，英文界面**只画一行**。
第 2 节那条硬约束 `node.y + node.r + 28 < 820` 是按两行算的，单行只会更松，
所以不用重新排坐标。

### 切换语言会重建整张星图

`buildMap()` 把 `gDefs` / `gEdges` / `gNodes` 清空重建，因此
`edgeEls` / `nodeEls` 是 `let` 不是 `const`。**重建后必须 `select(sel)`**，
否则详情栏会空白。`renderAll()` 里已经这么做了。

重建会丢事件监听，所以凡是有监听器的渲染都必须走 `renderAll()`，
不能只改 `innerHTML`。已经踩过的状态保持（都在 `renderAll()` 里处理了）：

| 状态 | 靠什么保住 |
|---|---|

### 语言的存取顺序

`?lang=en` / `?lang=zh` → `localStorage['odyssey-lang']` → `navigator.language`。
切换时写回 localStorage 并用 `history.replaceState` 更新 URL，
**两个都包在 try 里**——Artifact 沙箱和 `file://` 下可能被拦，拦了也不该影响页面。

URL 参数的意义是分享：发出去的链接会保持语言。

### 英文必须换字体栈，这不是审美问题

```css
:root[lang="en"]{
  --head:ui-serif,Georgia,…;
  --body:ui-sans-serif,system-ui,…;
}
```

**Noto Sans SC 把弯引号 U+2019 当成全角标点渲染**，左右各带巨大边距，
`Nolan’s` 会显示成 `Nolan’ s`。英文正文里撇号到处都是，不换栈整页都是这个毛病。
换栈后实测撇号宽度从十几 px 回到 3.4px。

`--display`（Cinzel）本来就是拉丁字体，不用动。

另外英文标题单独收了一档字号（`clamp(31px,4.2vw,48px)`）：
同一句话英文比中文长得多，按中文的 68px 会折成三行还带一个孤字。
**改 hero 标题文案时要重新量**——容器宽 1132px，每行别超过它。
